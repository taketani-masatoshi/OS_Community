# OrgOS と ISO 37000

共有インフラが「よい実務」を標準経路にするとき、オープンな協働は拡張します。**OrgOS** は、その考え方を組織統治に適用します。OrgOS を展開し、**初期化**の過程で組織を設定すると、目的・役割・監督・監査可能性を一体のベースラインとして確立できます。

そのベースラインは、**ISO 37000**（*Governance of organizations* — ガイダンス）への整合について、信頼に足る **自己宣言** を支えるものです。OpenOrgOS Community が発行する第三者 ISO 認証ではありません。

## コミュニティが提供するもの

OpenOrgOS Community は、プロトコル・モジュール・学習・オペレータ経路のための **中立な拠点（neutral home）** を提供します。統治に関する表明・方針・文化の責任は、各会員組織に留まります。

| 用語 | 定義 |
|------|------|
| **OrgOS** | 自組織が管理するインフラ上で運用する組織ランタイム（デジタルツインとモジュール） |
| **OOO** | [OpenOrgOS Operator](/certifications) — 展開と日常運用を主導する参考役割 |
| **ISO 37000** | 組織のガバナンスに関する国際的なガイダンス（目的・監督・説明責任など） |
| **自己宣言** | ガイダンスへの整合を組織自身が表明すること — 認定制度による認証とは区別される |

ISO 37000 は ISO 9001 のような認証要求事項規格ではなく **指針** です。組織は内部レビューやチェックリストで整合を確認することが一般的です。OrgOS は、その確認を初回展開から **運用可能で証拠に基づく** ものにします。

## 実証された手順: 初期化と統治を同時に進める

OrgOS は、組織設定と統治設定を後付けではなく、**一体の経路**として進めるよう設計されています。

1. **展開** — 自組織が管理する機器に OrgOS を導入する（[OrgOS 導入ガイド](/content/orgos-install-setup)）
2. **準備** — 本番前に組織事実を整理する（法人身元、体制、法域、モジュール方針）
3. **初期化** — テナント初期化時に体制を記録する（部署、役割、責任者）
4. **有効化** — 統治のベースラインを有効化する（提案、委員会、監査フックなど）
5. **運用** — 決定と変更の記録を残し、監督を証拠に基づくものにする

**OpenOrgOS Operator（OOO）**、または同等のスチュワードが、この経路を主導するのが一般的です。

## テーマ対応（例示）

次表は実務上の対応関係です。条項ごとの監査主張ではありません。

| ISO 37000 のテーマ（要約） | OrgOS の初期化が確立を助けるもの |
|---------------------------|----------------------------------|
| **目的（Purpose）** | 組織の身元と、テナントの存在理由 |
| **価値と戦略** | 初回採用と後続モジュールの優先順位 |
| **監督（Oversight）** | 役割、委員会、Org Console によるレビュー面 |
| **説明責任（Accountability）** | 指名された運用者と委任されたモジュール所有 |
| **ステークホルダー** | 内部体制、および準備が整えば組織間連携 |
| **リスクと誠実性** | 自組織インフラ上のデータ所在、初日から使える監査フック |
| **意思決定** | 非公式な口頭決定ではなく、統治された提案 |

統治機関が目的・価値・取締役実務を定義します。OrgOS はそれらを **実行可能で監査可能な形** にします。

## 「自己宣言の準備」の範囲

**範囲内**

- 自組織が管理するシステム上の、稼働する体制・役割・決定記録
- 取締役会やステークホルダー向けの、目的 → 体制 → 監督の説明経路
- ISO 37000 風の自己評価チェックリストを埋める実務ベースライン

**範囲外**

- OpenOrgOS Community による自動 ISO 認証または証明書の発行
- 法的助言、あるいは特定の宣言を規制当局が必ず受け入れることの保証
- 組織の方針と文化なしに、指針のすべてのテーマが完了すること

共有技術は能力を解放します。**説明責任は各組織に留まります。**
