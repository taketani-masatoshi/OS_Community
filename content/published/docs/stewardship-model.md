# スチュワードシップモデル

## 基本思想

ISO の規格領域ごとの専門委員会、PMP のプロジェクト管理専門家ネットワーク、Linux カーネルの MAINTAINERS ファイルと同様に、
本コミュニティは **モジュール単位の Maintainer 制度**（スチュワードシップ）を採用します。

| 比較 | ISO | 本コミュニティ |
|------|-----|--------------|
| 単位 | 規格領域（9001, 27001…） | 業務モジュール / 法域パック |
| 役割 | 専門委員・監査員 | Maintainer（メンテナ） |
| 性質 | 栄誉 + 専門責任 | 栄誉職（更新・監視・監査） |
| 更新 | 規格改定サイクル | モジュール version / readiness |

## 3 つの役割

OSS / Linux 慣習に合わせ、次の 3 役割を使います。

### Maintainer（メンテナ）

当該モジュールの **更新方針・品質・監視** の最終責任を担う栄誉職。
税務・法務・業種知見を持つ専門家が名乗りを上げるポジションです。

### Co-maintainer（共同メンテナ）

Maintainer を補佐し、更新レビュー・監査対応を分担します。

### Contributor（コントリビュータ）

PR・ドキュメント・seed データ等でモジュールに貢献するメンバーです。

## 参考資格（Operator / Designer）

スチュワードシップとは別に、**運用者（SO）** と **設計者（SD）** の参考資格を設けます。
PMP が「管理手法の習熟」を示すように、SO/SD は Steward OS の運用・設計能力の参考表示です。
法的保証や PMP® との同等性を意味しません。

## 参加方法

1. [GitHub でログイン](/login)
2. [モジュールレジストリ](/modules) から担当希望モジュールを選ぶ
3. Maintainer / Contributor として申請を提出
4. コミュニティ審査後、公開レジストリに掲載

## 存続と責任

- **第一責任**はモジュールの **作者 / Maintainer** にあります。
- 作者が存続不能になった場合、**当該ドメインまたは法域の委員会** がガバナンス規則に従いスチュワードシップを引き継ぎ得ます。
- **Commercial 販売・保守** の責任主体は Community ではなく、法域 **Hub コホート** です（Community のレビューは Commercial 背書きではありません）。

詳細は [モジュールエコシステム](/content/module-ecosystem) を参照してください。
