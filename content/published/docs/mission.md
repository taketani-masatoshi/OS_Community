OpenOrgOS は **組織の電子カルテ** です。組織間通信（inter-organizational communication）のグローバルプロトコルを、オープンソースコミュニティとして育てています。

病院では、患者のカルテを通じて診療の履歴・担当・委任・監査証跡を共有します。企業・大学・NPO・サプライチェーンも、組織境界を越えたやり取りを **検証可能な共通記録** として残す必要があります。OpenOrgOS は、そのプロトコル層を定義します。

> **組織内部の運営管理 OS ではありません。** 社内の人事・勤怠・ワークフローの置き換えが目的ではなく、組織間で状態を交換する関係のための共通言語です。

## 組織の電子カルテ — 比喩の対応

| 医療の電子カルテ | OpenOrgOS |
| --- | --- |
| 共有カルテ | 組織間の構造化された共通記録 |
| カルテ記載（診療イベント） | **Org Event Model** — 契約・委任・状態変化 |
| 患者 ID | **Identity Exchange** — 組織・主体の同一性 |
| 紹介・受診手続 | **Authority Delegation** — 権限の委任とスコープ |
| 監査証跡 | **Auditability** — 第三者が検証できるタイムライン |

## グローバルプロトコルが定義するもの

| 定義 | 内容 |
| --- | --- |
| **Org Event Model** | 組織間で交換するイベントの共通モデル |
| **Identity Exchange** | 組織・主体の同一性の交換 |
| **Authority Delegation** | 委任された権限・スコープ・代理行為の標準化 |
| **Auditability** | 第三者が検証できる監査可能性 |

## 委員会への委任

**ビジネスロジック・法解釈・組織行動は、各国・各ドメインの委員会に委ねられます。**

グローバル層はプロトコルのみを定義します。会計・契約・労務・業界規制など、ローカルな意味と実装は **national or domain-specific committees**（各国・各ドメイン委員会）が担います。

## 人が読めるルール

基本形式は **Markdown や YAML** など、人が読めるルールです。

- AI がルールを処理する
- 人がルールをメンテナンスする
- 監査可能で信頼できるプロトコルを育てる

モジュールは、プロトコルを法域・業界・ユースケースごとに実装する単位です。内部の人事・勤怠など **組織内運用の置き換え** が目的ではありません。

## Open の意味

**Open** は、利用するすべての人々の力と意見を取り入れる思想です。

提案、レビュー、標準化、モジュール開発 — 誰もが参加できるオープンソースコミュニティとして育てます。

## 適用範囲

企業間取引、大学・研究機関の共同、NPO 連携、サプライチェーン、ジョイントベンチャーなど、**組織境界を越えて検証可能な状態を交換する必要がある関係** に適用できます。

## メンバーシップ

**Contributor・Reviewer などへの参加は、専門分野・地域を問わず広く歓迎** します。

一方、**自分の専門分野・地域以外の委員会** への参加には基準を設けます。例えば日本人が中国向け委員会に参加する場合、同じ専門分野（会計・契約など）における深い知見があり、法域間のルールを橋渡しできることが望ましいです。

詳細は [ガバナンス](/governance) を参照してください。

## 公開範囲と企業資産の保護

OpenOrgOS は **競争領域を標準化する OS ではありません**。組織間で共通化するのは **交換プロトコル** であり、製品・顧客・ノウハウ・戦略など **競争資産は各企業が保護** します。

モジュールは **Community Module（公開）** と **Private Module（非公開）** を自由に組み合わせ可能です。コミュニティへの還元は歓迎しますが、義務ではありません。

詳細は [公開範囲および企業資産保護ポリシー](/governance/openness) を参照してください。
