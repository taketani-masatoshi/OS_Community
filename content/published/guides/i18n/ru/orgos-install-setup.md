> **Обзор:** [Что такое OrgOS?](/learning#about-orgos) в учебном центре — детерминированное ПО, работа с ИИ на естественном языке и расширение модулями.

Это руководство для **Steward Operator** при первом развёртывании: требования, информация до `tenant init` и база **цифрового двойника** (оргструктура, модули, аудит).

**Бизнес-данные OrgOS остаются на вашей инфраструктуре**. OpenOrgOS Community (`openorgos.net`) предоставляет протокол, реестр модулей и обучающие материалы — не данные tenant.

## Для кого

| Роль | Цель |
|------|------|
| **Steward Operator** | Запуск Org Console на корпоративном оборудовании с минимальной IT-поддержкой |
| **Основатель / спонсор** | Понять, что подготовить до go-live |
| **Steward (консультант)** | Проверить среду клиента перед передачей |

## Результаты

1. Подходящая машина для OrgOS на Docker
2. Чеклист организационных фактов (структура, юрисдикции, модули)
3. Инициализированный tenant с проверенной конфигурацией
4. Минимальный объём цифрового двойника: оргструктура, активные модули, аудит

## Фаза 0 — Сначала собрать информацию

До `tenant init` подготовьте:

### Идентичность организации

- Юридическое название, торговые имена, основные юрисдикции
- Финансовый год и отчётная валюта
- Ежедневный контакт **Steward Operator**

### Структура (зерно двойника)

- Отделы / команды и линии подчинения
- Ключевые роли — сопоставьте с [агентами Steward](/agents)
- Внешние стороны для обмена org events

### Намерения по модулям

Изучите [реестр модулей](/modules#registry):

| Область | Примеры | Запуск? |
|---------|---------|---------|
| Управление | предложения, комитеты | Часто да |
| Финансы | счета, договоры | По необходимости |
| Операции | склад, расписание | По необходимости |

### Границы данных

- Что **никогда** не должно покидать Mac mini (PII, договоры, детали учёта)
- Что можно обобщить в опциональных SaaS-дашбордах (только чтение)

## Фаза 1 — Оборудование и сеть

| Компонент | Назначение |
|-----------|------------|
| **Mac mini** (или всегда включённый хост) | Org Runtime + Org Console — **источник истины** |
| **Synology NAS** (опционально) | Резервные копии |
| Стабильная LAN | Внутренний доступ к Org Console |
| Исходящий HTTPS | GitHub, реестр, опциональный heartbeat |

## Фаза 2 — Программные требования

```bash
docker --version
docker compose version
git --version
```

- Аккаунт **GitHub** с доступом к репозиторию OrgOS / Steward
- Аккаунт OpenOrgOS Community на [openorgos.net](/login)
- `.env` только на хосте — не коммитьте учётные данные

## Фаза 3 — Клонирование и настройка

```bash
git clone https://github.com/steward-os/steward.git
cd steward
cp .env.example .env
# Измените: TENANT_SLUG, JURISDICTION, ENABLED_MODULES, DATABASE_URL, AUTH_*
docker compose up -d
curl -sk https://localhost/health
```

Исправьте ошибки health check перед продолжением.

## Фаза 4 — `tenant init` и validate

```bash
./scripts/tenant-init.sh
./scripts/validate.sh
```

Следуйте README репозитория steward. Устраните все ошибки до go-live.

## Фаза 5 — Базовая линия цифрового двойника

| Слой | Настройка |
|------|-----------|
| **Identity** | Люди, роли, связанные аккаунты |
| **Authority** | Делегирования, scope комитетов |
| **Events** | Org events от модулей |
| **Agents** | [Реестр агентов](/agents) |

- [ ] Роли executive и finance назначены реальным людям
- [ ] В Console виден хотя бы один тестовый org event
- [ ] Активные модули задокументированы в runbook
- [ ] Резервное копирование проверено (DB + config)

## Устранение неполадок

| Симптом | Вероятная причина |
|---------|-------------------|
| Сбой OAuth | URL браузера ≠ `AUTH_URL` в `.env` |
| Ошибка БД | Неверный хост `DATABASE_URL` в Docker |
| Модуль не загружается | Нет в реестре или OFF при tenant init |
