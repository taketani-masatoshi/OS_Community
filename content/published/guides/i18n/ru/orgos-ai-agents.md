> **Обзор:** [Что такое OrgOS?](/learning#about-orgos) в учебном центре — детерминированное ПО, управляемое через LLM и AI-агентов на естественном языке.

**Предварительное условие:** завершено [руководство по установке и цифровому двойнику](/content/orgos-install-setup) или работает локальный tenant.

## Что делают агенты

| Возможность | Пример |
|-------------|--------|
| **Объяснять** | «Что разрешает manifest агента finance?» |
| **Навигировать** | «Какие модули включены для этого tenant?» |
| **Черновик** | «Сгенерируй шаблон предложения комитета для юрисдикции JP» |
| **Проверять** | «Запусти validate и суммируй ошибки» |
| **Эксплуатация** | «Покажи открытые org events для operations на этой неделе» |

Агенты **не заменяют управление**. Утверждения, делегирования и правила аудита действуют — относитесь к агенту как к **ассистенту Steward**, а не автономному руководителю.

## Как это устроено

```text
Вы (естественный язык)
    ↓
Агент Cursor (читает repo + инструменты)
    ↓
Репозиторий steward — agent.manifest.yaml, модули, скрипты
    ↓
Org Runtime / Org Console (локально — данные остаются здесь)
    ↓
Опционально: OpenOrgOS Community (только публичный протокол и реестр)
```

Определения агентов в `steward/agents/`. [Реестр агентов](/agents) Community — публичный каталог; tenant может расширять локально.

## Шаг 1 — Открыть workspace steward

1. Клонируйте репозиторий Steward / OrgOS организации (тот же хост, что Org Console).
2. В Cursor: **File → Open Folder** → корень репозитория.
3. Проверьте дерево агентов, напр. `steward/agents/executive/agent.manifest.yaml`.

Дождитесь индексации для работы `@Codebase`.

## Шаг 2 — Правила проекта (рекомендуется)

`.cursor/rules/orgos.mdc` или **Cursor Settings → Rules**:

- Не вставляйте бизнес-данные и секреты `.env` в публичные чаты
- Перед записью предпочитайте только чтение
- Соблюдайте юрисдикцию и границы модулей из `tenant.yaml` / `.env`
- Запускайте `./scripts/validate.sh` после изменений config

## Шаг 3 — Подключить контекст

| Источник | Как прикрепить в Cursor |
|----------|-------------------------|
| Config tenant | `@.env.example`, `@tenant.yaml` (редактированный) |
| Оргструктура | `@exports/org-chart.csv` |
| Список модулей | `@modules/enabled.json` или ссылка на реестр |
| Заметки onboarding | `@docs/onboarding-checklist.md` |
| Реестр агентов | `/agents` или `@steward/agents/` |

## Шаг 4 — Паттерны естественного языка

### Исследование (только чтение)

- «Суммируй, что может compliance vs finance.»
- «Объясни путь org event от модуля X до audit log.»

### Конфигурация (черновик → ревью)

- «Черновик списка модулей для сервисной компании 20 человек в JP — таблица.»
- «Объясни вывод validate.sh построчно» (после запуска в терминале)

### Эксплуатация (осторожно — только локально)

- «Перечисли скрипты, затрагивающие production-данные; классифицируй read vs write.»

Избегайте деструктивных команд без явного одобрения человека.

## Шаг 5 — Реестр агентов

[Реестр агентов](/agents) сопоставляет домены:

| Агент | Домен | Типичные вопросы |
|-------|-------|------------------|
| executive | governance | Стратегия, утверждения |
| secretary | governance | Расписание, протоколы |
| finance | finance | Счета, учётная политика |
| contract | finance | Жизненный цикл договоров |
| compliance | finance | Регуляторные проверки |
| operations | operations | Операционные очереди |

Синхронизируйте локальные manifest после обновлений реестра (`npm run sync:agents`).

## Шаг 6 — MCP и терминал (опционально)

- Сначала **только чтение** MCP
- Терминал: `docker compose ps`, `validate.sh`, логи — вставьте вывод в чат
- Не открывайте admin-порты Org Console в интернет

## Чеклист безопасности

- [ ] Агент работает с **локальным** clone steward
- [ ] Секреты `.env` — агент видит только placeholders
- [ ] Запись проверяет Steward Operator
- [ ] Validate проходит после правок от агента
